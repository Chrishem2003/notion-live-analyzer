# Shared Ollama gateway (zero model-API spend)

This setup lets the hosted platform call the Ollama model running on the Windows model host. It is **not** a permanently hosted, always-available inference service: the Windows PC, Ollama, gateway, and secure tunnel must be online. A zero-cost Render service cannot host the Qwen model itself.

## Security rules

- Do not expose port `11434` directly.
- Run `ollama_gateway.py` bound to loopback only (`127.0.0.1:11435`).
- Use a random secret of at least 32 characters. Keep it out of Git and chat logs.
- Publish only port 11435 through a TLS tunnel. The gateway validates a bearer token on all Ollama API routes.
- Never set the secret in Streamlit UI/session state or send it to browser code.

## Windows PowerShell — model host

From the repository folder, with the existing Python environment active:

```powershell
# Create a strong secret and copy it directly into a password manager temporarily.
$bytes = New-Object byte[] 32
[System.Security.Cryptography.RandomNumberGenerator]::Fill($bytes)
$token = [Convert]::ToBase64String($bytes).TrimEnd('=').Replace('+','-').Replace('/','_')
$env:OLLAMA_GATEWAY_TOKEN = $token
$env:OLLAMA_UPSTREAM_URL = "http://127.0.0.1:11434"

# Confirm Ollama is running and the model is installed.
ollama list

# Start the authenticated gateway on loopback only.
python -m uvicorn ollama_gateway:app --host 127.0.0.1 --port 11435
```

Keep that terminal running. In a second terminal, configure a TLS tunnel whose local target is `http://127.0.0.1:11435`. Use a stable hostname if you have a domain/tunnel provider that supports one. A temporary quick-tunnel URL is for testing only because it can change.

## Render — hosted Streamlit service

Set these as **server environment variables** on `notion-live-analyzer` (do not replace the existing environment variables):

- `OLLAMA_BASE_URL` = the tunnel's HTTPS origin, with no trailing slash and no `/api` suffix.
- `OLLAMA_MODEL` = `qwen2.5:3b`
- `OLLAMA_API_KEY` = the exact same random secret as `OLLAMA_GATEWAY_TOKEN` on the model host.

Only configure the variables after the tunnel is live and the URL is verified. If the API service or another app uses the shared router, configure the same variables there as well, merging them into existing environment settings.

## Verification and operational limits

1. From the host, check `http://127.0.0.1:11435/health` returns `{"status":"ok"}`.
2. Check that `/api/tags` without a bearer token returns HTTP 401; do not test by exposing Ollama directly.
3. Configure the HTTPS tunnel and check that the hosted app's **Check Ollama connection** succeeds.
4. Sign in with a normal user account and send a harmless test prompt. Confirm the response is generated by the configured Ollama model.
5. Stop the tunnel and repeat: the workspace should show an unavailable message and must not send the prompt to a paid provider.

For a permanent all-user service, the model host must stay online and have adequate CPU/RAM/network capacity. This local-host arrangement has no model API fee but is not an always-on cloud service. Do not advertise production-grade availability until uptime, concurrency limits, rate limits, monitoring, and account-level quotas have been tested.
